# План исследования A3Pay × Ozon Банк

## Тип работы

`standalone deep research + payment-flow design + FigJam-ready handoff`.

## Цель

Определить проверяемый MVP, в котором покупатель с доступом к Ozon Банку оплачивает покупку у внешнего мерчанта через A3Pay, а мерчант получает понятные способы подключения, статусы, возвраты и сверку.

## Этапы

1. Проверить публичные факты об А3, Ozon Pay/Ozon Банке, СБП, тарифах и нормативных ограничениях.
2. Разделить подтвержденные возможности, партнерские предположения и недоступные без API ответы.
3. Описать customer-side happy path и негативные ветки: нет приложения/счета, неверный номер, нет push, недостаточно средств, отказ, timeout, дубль, возврат.
4. Описать merchant-side путь: подключение, KYB, интеграция, создание платежа, callback/polling, фискализация, сверка, возврат, поддержка.
5. Сравнить варианты MVP и выбрать рекомендуемый маршрут с критериями go/no-go.
6. Подготовить FigJam-ready карту, затем записать ее только после фиксации exact target и approval record.
7. Выполнить research lint, workflow sync/inspect и зафиксировать остаточные риски.

## Inputs used

- Запрос пользователя от 2026-06-18.
- `AGENTS.md` и `research/README.md`.
- Старый A3Pay run используется только как навигационный фон, не как источник текущих фактов.
- Публичные первичные и вторичные источники заносятся в `source-log.md`.

## Definition of Done

- Есть source-backed вывод по реализуемости каждого MVP-варианта.
- Есть customer и merchant workflow со статусами и recovery paths.
- Комиссионное сравнение не подменяет СБП рекламным тезисом.
- Есть список вопросов к A3/Ozon Банку, без ответов на которые нельзя обещать production behavior.
- FigJam-ready структура покрывает обе стороны и системный lifecycle платежа.
